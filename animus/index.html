The Animus Project

Intelligence that stays home.

Put inference on hardware you control, with an agent workflow designed around your tools and data. Animus Ferric is a public Rust project built for small local models (1B–14B GGUF). It informs the custom harness and local LLM deployment services offered here; each workload and hardware combination needs its own evaluation.

The lineage

Four implementations to get it right.

Animus wasn't designed in one sitting — it was earned. Three earlier implementations are dormant in public repos, and each one taught us something the next one kept. That history is the feature: every conviction in Ferric was paid for with working code.

  1. Python

    Animus

    The original prototype: an open-source, natively running agentic CLI. It explored the local-agent workflow and established the starting point for later work on bounded tool use and execution traces.

  2. Go

    Animus Prion

    The rebuild for speed and static binaries. Prion sharpened the tool-calling loop and showed how much discipline small models need from the harness around them.

  3. Go

    fev

    A local-first assistant for navigating the digital space. fev explored the personal-agent side of the problem and clarified what belongs in the harness versus the model.

  4. Rust Active

    Animus Ferric

    The Rust synthesis of the earlier implementations: a harness that owns decoding, scales its behavior to the model, and treats the trajectory as the source of truth.

The convictions

Three rules, paid for in working code.

01

The harness owns decoding

Constrained generation — JSON-Schema, regex, and CFG grammars — is requested by the harness and enforced by supported inference backends. This constrains tool-call structure. Valid structure does not guarantee a correct action, so tool validation, permissions, and evaluation still matter.

02

Behavior scales to the model, deterministically

A pure function maps a model profile — parameters, quantization, context, measured capability — to a run policy: protocol, plan granularity, turn budgets, tool count. A 3B model gets 3B-sized steps. No guesswork, no vibes.

03

The trajectory is the source of truth

Every session writes a versioned JSONL trace — full conversation, tool calls, untruncated output, execution chain — replayable and diffable. If it isn't in the trace, it didn't happen.

Explore Ferric's public source and documentation, including the project's current licensing information. What I sell is the implementation work: making local agents work on your hardware, against your codebase, inside your security boundary.

Custom harness implementations

Ferric (or a purpose-built harness) adapted to your environment: your tool surface, your permission model, your models. Constrained decoding tuned to the workflows your team actually runs.

Edge AI deployments

llama.cpp servers with custom harnesses on workstations, on-prem servers, and Jetson-class edge devices. The scope can include model selection, quantization, serving, and the agent loop, with hardware support verified against the chosen inference backend.

Local-agent strategy

Not sure whether a 7B model on your hardware can carry your workload? Ferric includes a capability ladder (L0–L6) for evaluating model behavior. We can scope a benchmark using representative tasks and your hardware, then use the results to guide an implementation decision.
